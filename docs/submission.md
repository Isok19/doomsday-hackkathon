# Сдача результатов — команда zenoxxk

Формат: CQA Results 1.0 из дополнения организаторов. Срок команды — 8 ноября 2026, 11:50 (Asia/Almaty).
До этого времени должны завершиться обработка, проверка, commit **и push**.

| Набор | Состав | Действие |
| --- | --- | --- |
| DEV | 60 чатов + 5 звонков | Основной чек-лист → `results/dev/results.json` |
| FBroker | 10 контрольных чатов | Основной чек-лист → `results/prod/results.json` |
| SWAP | 3 дополнительных чата | Только локальное сохранение; ждать новой инструкции |

Исходные JSON сохраняются в `data/` и SQLite; в Git не отправляются.
Папки `results/dev/` и `results/prod/` подготовлены. Пустые или вымышленные results.json не создаются.

## Запуск и продолжение

После настройки `OPENAI_API_KEY` и `CQA_ENABLE_AI=1` в окружении терминала:

```bash
.venv/bin/python -m participant_3.batch run --group FBroker --split prod --resume
.venv/bin/python -m participant_3.batch run --group DEV --split dev --resume
```

Начинайте с контрольного набора. Обработка последовательная, таймаут одного API-вызова 90 секунд;
планируйте время по первому реальному ответу. Нет автоматических повторных платных запросов.
`--resume` пропускает успешные оценки того же чек-листа/версии, модели, версии промпта и базы знаний.
Успехи и ошибки сохраняются после каждого диалога, поэтому перезапуск не теряет историю.
Ошибки можно повторить после исправления причины. Выгрузка берёт последнее состояние попытки.

Ключ, введённый через `participant_3.serve`, живёт только в серверном процессе, а не в другом терминале.
В этом режиме можно оценивать карточки через UI/API и затем выполнить `export` без ключа:

```bash
.venv/bin/python -m participant_3.batch export --group FBroker --split prod
.venv/bin/python -m participant_3.batch export --group DEV --split dev
```

Кнопка **Выгрузить результаты** в списке диалогов делает ту же проверку и скачивает файл.
Сохраните его в папке соответствующего набора. Экспорт не выполняет push.

## Что проверяет экспорт

- Исходные `conversation_id`: все 65 DEV или 10 FBroker, без дублей и посторонних ID.
- Все восемь критериев ровно по одному на успешный диалог.
- `contact`, `discovery`, `identification`, `consultation`, `empathy`, `dialogue`, `closure`, `critical`.
- Типы значений, допустимые ступени, N/A, расчёт итогового балла и отдельный `critical_flag`.
- `evidence_turns` с 1 по полному исходному транскрипту, включая клиента, бота и систему.
- `model.mode/name` по сохранённым метаданным реального оценщика; отсутствие происхождения блокирует экспорт.
- Ошибка: `status=error`, `criteria=[]`, `score=null`, непустое `error`. Ошибка не заменяется нулём или N/A.
- UTF-8, обычный JSON без комментариев; файл заменяется атомарно после успешной проверки.

По умолчанию сдаётся исходный основной чек-лист `cqa-default`, версия 1. Внутренние коды
`needs/identity/management/closing` преобразуются в официальные только в экспорте.
Изменённые веса и шкалы или неполный набор критериев не экспортируются в официальный формат.
Учитывается финальный результат с решениями апелляций; оригинал и решения остаются в SQLite.
Проверьте обоснования перед публичной сдачей: не включайте персональные данные или подписанные ссылки.

## Перед отправкой

```bash
.venv/bin/python -m participant_3.batch validate --group FBroker --split prod
.venv/bin/python -m participant_3.batch validate --group DEV --split dev
git add results/dev/results.json results/prod/results.json README.md
git commit -m "Submit DEV and FBroker CQA results for zenoxxk"
git push origin main
```

Это инструкция для фактических файлов после обработки, а не подтверждение уже выполненной сдачи.
Проверьте оба файла на GitHub. В поле Git Link формы сдачи укажите
`https://github.com/Isok19/doomsday-hackkathon`. README содержит имя команды zenoxxk.
SWAP не включайте в PROD и не оценивайте до отдельной инструкции.

## Ограничение проверки

Валидный JSON и верная арифметика не доказывают точность ИИ. Человек должен проверить, что
доказательства действительно подтверждают вывод и что причины N/A соответствуют правилам.
Для проверки тарифов/процедур нужны материалы компании. Без них модель может потребовать ручную проверку;
такой результат честно экспортируется как ошибка обработки, а не как вымышленный балл.
