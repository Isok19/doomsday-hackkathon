# CQA — сервер участника 2

Первый этап серверной части на Python + FastAPI с локальной SQLite.
Работает с выданным `dialogs.json`: 65 диалогов, включая 60 чатов и 5 звонков.
Звонки содержат транскрипты и ссылки `audio_url`; скачивание и доступность записей пока не проверяются.

## Что реализовано

- Проверка формата JSON, успешности ответа, количества записей и уникальности ID.
- Атомарный импорт в SQLite. Повторный запуск с тем же набором не создаёт дубликаты.
- Хранение исходных реплик, ролей, текстов, меток времени и ссылок без преобразования.
- Список диалогов, фильтры языка и канала, постраничная выдача, карточка диалога.
- Устойчивые ID сообщений для будущих доказательств.
- Документация API в Swagger UI и интеграционные проверки на выданном DEV.

## Запуск в терминале VS Code

Выполняйте команды из корня открытого проекта. Используется Python 3.11 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

На Windows создание окружения: `py -m venv .venv`; активация в PowerShell:
`.venv\Scripts\Activate.ps1`. Остальные команды после активации одинаковые.

Откройте http://127.0.0.1:8000/docs — там можно вызвать каждый маршрут через Try it out.
По умолчанию при запуске файл `dialogs.json` импортируется в `data/cqa.sqlite3`.
Повторный запуск использует существующую БД. Исходный JSON не изменяется.
Если файл отсутствует или некорректен, запуск остановится с сообщением об ошибке.

В VS Code выберите Python-интерпретатор из `.venv`, если расширение Python уже установлено.

## API для участника 1

| Метод и путь | Результат |
| --- | --- |
| `GET /health` | Проверка, что сервер запущен |
| `GET /api/dataset` | ID активного набора, число диалогов и сообщений, распределение по языкам и каналам, число ссылок на записи |
| `GET /api/dialogs` | `total`, `limit`, `offset`, `items` — список без текстов сообщений |
| `GET /api/dialogs/{conversation_id}` | Диалог с исходной ссылкой на запись и полным транскриптом |

Параметры списка: `language` — RU/KZ/EN; `channel` — agent chat/voice call;
`limit` — от 1 до 100 (по умолчанию 100); `offset` — от 0.
`total` содержит число всех диалогов, подходящих под фильтры, до пагинации.
Порядок диалогов соответствует файлу организаторов.

Элемент списка содержит `conversation_id`, `dataset_group_id`, `language`, `channel`,
`message_count`, `has_audio`. Наличие ссылки не гарантирует доступность записи.
Карточка дополнительно содержит `audio_url` и `transcript`.
В сообщении сохраняются `timestamp`, `speaker`, `text`; добавлены `position` (с 1)
и `message_id` (UUID, получаемый из группы, ID диалога и позиции).
ID сообщений повторяются при повторном импорте неизменённого набора.
Для будущего модуля оценки передавайте ссылки на `message_id`, а не только текст цитаты.

Неизвестный диалог возвращает HTTP 404; неверные значения фильтров и пагинации — HTTP 422.
Точный машинный контракт доступен по `/openapi.json`.

## Настройки

Настройки читаются из переменных окружения. Файл `.env` автоматически не загружается.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `CQA_DATASET_PATH` | `dialogs.json` в корне проекта | Путь к JSON организаторов |
| `CQA_DATABASE_PATH` | `data/cqa.sqlite3` в корне проекта | Путь к локальной SQLite |
| `CQA_CORS_ORIGINS` | пусто | Разрешённые адреса интерфейса через запятую |

Адреса интерфейсов команды пока не согласованы, поэтому CORS по умолчанию не включён.
Когда участник 1 сообщит точный адрес с портом, задайте его в `CQA_CORS_ORIGINS`
и перезапустите сервер. Это отдельная настройка от загрузки данных организаторов.

БД хранит наборы раздельно по `dataset_group_id`; API показывает набор из текущего входного файла.
Если файл с тем же ID группы изменился, сервер остановится, не перезаписывая прежние данные.
Для независимой проверки такого файла задайте другой `CQA_DATABASE_PATH`.
Обновление уже оценённых диалогов требует отдельного согласования правил истории.

## Проверки

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Тестам нужен исходный DEV в `dialogs.json`. Тестовые БД создаются во временных папках.
Проверяются все 65 транскриптов и ссылки без изменения, повторный запуск, фильтры,
пагинация, ошибки данных и защита импортированного набора от перезаписи.
Вымышленных диалогов или оценок нет; отрицательные тесты меняют только структуру копий DEV.
